# 04 · Extension A: DNS failure (both dnsmasq down → "Could not resolve host", but ping and HTTPS by IP work) vs app failure (DNS fine, both backends down → 502 from the edge)

## vm4-backend-b
vks@vm4-backend-b:~$ # Part 1: both DNS servers down
vks@vm4-backend-b:~$ sudo resolvectl flush-caches; curl -sS https://app.teamvks.test/api/status
curl: (6) Could not resolve host: app.teamvks.test
vks@vm4-backend-b:~$ dig app.teamvks.test +tries=1 | grep -E "error|reached"
;; communications error to 192.168.64.11#53: connection refused
;; communications error to 192.168.64.13#53: connection refused
;; no servers could be reached
vks@vm4-backend-b:~$ ping -c2 -W1 192.168.64.12 | tail -2
2 packets transmitted, 2 received, 0% packet loss, time 1004ms
rtt min/avg/max/mdev = 1.528/1.556/1.585/0.028 ms
vks@vm4-backend-b:~$ curl -sS --resolve app.teamvks.test:443:192.168.64.12 -o /dev/null -w "by IP, no DNS: %{http_c
ode}\n" https://app.teamvks.test/api/status
by IP, no DNS: 200
vks@vm4-backend-b:~$ # Part 2: DNS back up, both backends down
vks@vm4-backend-b:~$ sudo systemctl stop teamvks-backend; systemctl is-active teamvks-backend
inactive
vks@vm4-backend-b:~$ dig +short app.teamvks.test; curl -sS https://app.teamvks.test/api/status | grep -oE "<title>.
*</title>"
192.168.64.12
<title>502 Bad Gateway</title>
vks@vm4-backend-b:~$ # Restore: start both backends
vks@vm4-backend-b:~$ sudo systemctl start teamvks-backend; systemctl is-active teamvks-backend
active
vks@vm4-backend-b:~$ sleep 10; for i in 1 2 3 4; do curl -si https://app.teamvks.test/api/status | tr -d "\r" | gre
